# bexio: connect with a Personal Access Token, push customers and invoices

**Status: implemented 2026-09-05, awaiting the owner's first real push** (owner: "mam dostęp do miesięcznego
bezpłatnego konta bexio, jak podłączyć api").

## What bexio offers (checked 2026-09-05)

- **Personal Access Token** (developer.bexio.com → Personal Access Tokens):
  full access to one company, valid 60 days, sent as
  `Authorization: Bearer <token>`. No OAuth app registration needed.
- Contacts: `POST /2.0/contact` (`contact_type_id` 1 = Firma, 2 = Person;
  `name_1`, `name_2`, `address`, `postcode`, `city`, `mail`, `phone_fixed`,
  `user_id`, `owner_id`), `POST /2.0/contact/search`.
- Invoices: `POST /2.0/kb_invoice` (`contact_id`, `user_id`, `title`,
  `is_valid_from`, `is_valid_to`, `mwst_type` 1 = exkl., `mwst_is_net`,
  `api_reference`, `positions[]` of `KbPositionCustom` with `amount`,
  `unit_price`, `text`, `tax_id`), `POST /2.0/kb_invoice/search`.
- Reference data: `GET /3.0/users/me`, `GET /3.0/taxes?scope=active`.
- Payroll hours have no API; they stay in the CSV export.

## Design

- **The token never reaches the browser's storage or the repo.** The
  owner pastes it once on the Cockpit; the app sends it to the Worker,
  which checks it against `GET /3.0/users/me`, encrypts it (AES-GCM with a
  key derived from the Worker secret `BEXIO_TOKEN_KEY`) and keeps it in
  KV under the company. Without the secret the endpoint answers 503 and
  the card says so.
- Worker `worker/src/bexio.js`: `PUT /bexio/<cid>/token`,
  `GET /bexio/<cid>/status`, `DELETE /bexio/<cid>/token`,
  `POST /bexio/<cid>/push` `{ contacts?, invoices?, dryRun? }` — owner
  only. Pure mapping (`contactPayload`, `invoicePayload`, `pickTax`,
  `positionsOf`) tested with a fake bexio; a dry run returns the payloads
  it would send.
- Idempotent: a customer already in bexio (same e-mail or same name) is
  reused, and the bexio id is remembered per customer; an invoice with the
  same `api_reference` (our number) is not created twice.
- App: Cockpit card **bexio** (owner): connect form, status (user, since,
  token age with a renewal hint at 50 days), "Kunden nach bexio",
  "Rechnungen <Monat> nach bexio", dry run toggle, per-item results;
  bexio's error text is shown verbatim so a rejected field can be fixed.
- i18n ×14.

## Definition of done

- Worker tests: token saved only after bexio accepts it, encrypted at
  rest, status, push contacts (create/reuse), push invoices (tax picked by
  rate, positions mapped, duplicates skipped, dry run), errors surfaced,
  non-owner refused, missing secret → 503.
- Render test: the owner's Cockpit shows the bexio card with the token
  form.
- The owner connects the real account and pushes the customers; the
  first invoice push is verified in bexio by the owner (the Worker shows
  bexio's answer either way).

## Out of scope

- OAuth app flow (needed only for a multi-firm marketplace listing).
- Payroll hours (no API).
- Paying invoices back into Site Log.
